# Phase 2b — Guile 3.0.11 architecture and implementation design

Build a source-booted Jolt on Guile with a Chez-minted compiler, native OS threads, checked Scheme primitives and a small C extension. The first usable application is the Yin REPL with an in-memory store. The final store test opens durable stores from separate Yin processes, exchanges data over UDP and recovers the same bytes after restart. Phase 6 then verifies parity and the exact toolchain pin.

The baseline is `guile/audit` at `f5c80d00`. Its thirteen witnesses passed on Darwin arm64. Linux x86-64, standalone fence ordering in Jolt, and the public foreign-pthread callback bridge still need qualification. Witness numbers below refer to that baseline. The call shapes and permitted degradations come from the adapter contract. ## Threading, publication and control

**Fork and synchronization.** Wrap `(ice-9 threads)`'s `call-with-new-thread` as `fork-thread`, returning its thread object. Mark Jolt multithreaded before a second thread can execute Jolt, including first foreign entry. Implement `make-thread-parameter` with Guile's inheriting fluid-backed `make-parameter`. A child sees the creator's current dynamic binding at fork. A later parent rebind or child `(*txn* #f)` affects only its own binding. Keep truly thread-local internal state, such as virtual registers, on fresh per-thread storage. Exercise an agent or callback that relies on implicit conveyance.

Use the native `(make-mutex 'allow-external-unlock)` for each adapter mutex, accepting the optional diagnostic name used by host code. The kind makes owner re-acquisition wait. Host monitors retain owner/count policy. Acquire/release use `lock-mutex`/`unlock-mutex` and `with-mutex` unwinds reliably. Wrap native condition variables, signal and broadcast. Wait atomically releases the held mutex and returns with it held, including on timeout. Convert a host duration to the native deadline at the boundary. Test the signaled predicate under the mutex, broadcast to multiple waiters, an unsignaled timeout and a timed self-acquire. Use SRFI-19 for zero-argument UTC and explicit clock types, and adapt duration-valued `sleep` preserving subsecond delays.

Use a mutex-protected weak-key identity table from Guile thread object to a monotonic exact numeric ID. Both `get-thread-id` (current thread) and `sa-thread-id-of` (given thread) use the same lookup-or-assign operation. The latter checks `thread-exited?` and returns `#f` for an exited thread. The parent can assign a live child's ID before the child's first safe point. Test that ID from both ends of a synchronized fork, concurrent distinct IDs and a lookup after join. [w2](witnesses/w2-threads.scm)

**Standalone fences and the published word.** Export two fixed-arity C11 functions taking no arguments. Their bodies call `atomic_thread_fence(memory_order_release)` and `atomic_thread_fence(memory_order_acquire)` respectively. Bind them as effectful zero-argument Guile calls to `memory-order-release` and `memory-order-acquire`. Fail adapter startup if either is unavailable. In 3a inspect optimized C and Guile VM/JIT lowering for the target, including compiler ordering across the calls. A release fence must keep initialization before publication. The corresponding acquire must keep subsequent dereferences after observation.

The word that carries the tail supplies the cross-thread synchronization. In the Guile record transformer, back shared mutable publication fields with GC-traced `(ice-9 atomic)` atomic boxes. The initial correctness-first implementation can use a box for every mutable record field. A field's constructor initializes it once. Its generated accessor, setter and indexed `sa-record-cas!` all address the **same box**, using sequentially consistent ref, set and compare-and-swap. Use identity comparison of the returned old value for strong CAS success. Preserve logical field indices across inheritance and the raw record's GC reachability. Implement `box/unbox/set-box!` and `sa-box-cas!` coherently as well. Audit direct field/vector access that bypasses these accessors and route concurrently published words through the same atomic storage. Payload records and vectors can be initialized with ordinary writes before publication.

In `cseq-publish-tail!`, initialization precedes the release fence and atomic tail store. In `cell-force-claimed!`, both claim installation and replacement with the result operate on that tail. In `force-claimed!`, acquiring the claim precedes the body and releasing it follows publication. In `seq-more` a reader can take the realized-tail fast path without executing an explicit acquire fence. Its generated tail accessor therefore **must perform an acquire or stronger load**. The load observing the released word orders later payload reads. Apply the same rule to lazyseq thunk and claim fields in `lazy-bridge.ss`. A C fence alone cannot turn unrelated, unsynchronized accesses into this handoff. [Publication sites](../chez/seq.ss) · [Lazyseq consumers](../chez/lazy-bridge.ss) · [C11 fence synchronization, §7.17.4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)

Gate the compiled helper and actual accessors together. Race two OS-thread forcers on fresh cells, count thunk invocations, validate all fields of a newly built tail and its vector payload through the fast reader, and exercise claim rollback after an exception. Include the plain tail-set path as well as CAS publication. Use barriers only for starting rounds and reporting completion, so the harness cannot publish the payload on behalf of the code under test. Include failed-CAS and deliberately incomplete-payload controls. Run on arm64 and x86-64. The w2 fence-word smoke test establishes neither this ordering argument nor coverage of these paths.

**Shared tables on native pthreads.** In 3a audit the shared `host/chez/` manifest as well as Guile's kernel. Chez's bucket-vector snapshot guarantee does not carry over to Guile. On Guile synchronize at the registry or cache accessor: take the writer's mutex for every read of mutable table structure, including hits, size, key enumeration and nested weak-key lookups. Keep a lookup-and-install or multi-table update in one critical section. Use internal lock-held helpers for callers already holding the nonrecursive mutex. Preserve the Chez and Gambit fast paths through target-selected accessors. [Chez read assumptions](../chez/rt.ss)

## Native interface, GC and files

**Procedures and errors.** In Phase 3, the adapter uses private fixed-arity primitives for essential platform operations. Bind the public FFI names with their actual procedure or syntax shape and a message-carrying refusal until the Phase 4 `sizeof :int32` qualification or the Phase 5 ABI gates cover them. In Phase 5, implement typed syntax over a common runtime signature constructor using `(system foreign)` and `(system foreign-library)`. Translate the host type vocabulary, signedness, native widths and pointer integers at this boundary. Expose explicit alloc/free, typed reads/writes, sizeof, zero and overlap-safe byte transfers. Bulk moves are short synchronous calls with a strong reference to the Scheme bytevector through return. Keep argument owners live through the call and result conversion, including temporary UTF-8 storage. Non-moving GC permits paired no-op `sa-lock-object` and `sa-unlock-object`. Liveness still requires a reference.

Retain each loaded library handle for the lifetime of its procedures. Resolve the declared library's symbol first, then the process namespace where the public API permits it. Handle an address-valued procedure and a missing symbol explicitly. `sa-foreign-entry?` answers a boolean. Lookup requiring the entry and `load-library` report the symbol/path and cause on failure. Exercise colliding symbol names in two local libraries and a library with a missing dependency.

`sa-foreign-procedure-native-error` constructs the actual call with `#:return-errno? #t`. Consume its two values (C result, captured errno) before Jolt conversion or cleanup. There is no late errno lookup. `sa-foreign-procedure-blocking` uses the ordinary Guile call path on the audited build, including boundary errno capture when requested. W5 observed another thread allocating and completing collections strictly during a C blocking interval. Require the same bracketed C-active flag, changing GC count, intact live data and post-drain control through the **public binding** on each platform. [w4](witnesses/w4-errno.scm) · [w5](witnesses/w5-blocking-gc.scm)

**Callable ownership.** For a callback on a thread already in Guile mode, build the typed trampoline with `procedure->pointer`. Before exposing its integer entry address, insert the returned **`<pointer>` object** and its owners into a mutex-protected strong registry keyed by that address. Use one registry for adapter entry extraction and public `jolt-ffi-register-callable!`, with idempotent registration. Keeping an integer address alive loses the trampoline under GC (w4). Retain it until the C owner unregisters and quiesces its callers, then have `free-callable` atomically remove the entry once. A callback with no release remains live for the process. Never hold the registry mutex across a user callback, blocking join or foreign call.

For `sa-foreign-callable-collect-safe`, allocate a C libffi closure with `ffi_closure_alloc` and `ffi_prep_closure_loc`. Retain the CIF, type arrays, executable closure, entry pointer and protected Scheme procedure together. The native handler passes a plain C invocation context (args, return storage, closure context) to a `void *(*)(void *)` worker via `scm_with_guile`. Only the attached worker may box arguments, call `scm_call_n`, convert the result and touch Scheme state. Contain exceptions at the entry barrier, restore active counts on every exit, and specify the failure result for each admitted signature before exporting it. The native owner drains calls before `free-callable`: detach the registration so no new caller can obtain the address, then join or otherwise synchronize with every caller that could already hold it, through return **out of the trampoline**. The owner performs that wait outside the registry mutex. `free-callable` then removes the root once and releases the closure and CIF synchronously. A free from inside the active callback raises a catchable in-use error and leaves the registration rooted for later release by the owner. Phase 5 must test self-free and a delayed foreign return during detach. An active-count drop inside the libffi handler alone cannot prove its caller has left the executable trampoline. Roll back partial allocations on setup failure. W7 proves the attachment requirement. A Phase 5 test must invoke the *returned entry address* from two concurrent foreign pthreads, survive forced GC with Scheme-local references dropped, check distinct results, then detach, join and free. [w7](witnesses/w7-fthread.scm) · [Public callable lifetime](../chez/java/ffi.ss)

**Heap and clocks.** `sa-bytes-allocated` reads one `(gc-stats)` alist and computes `heap-size - heap-free-size` from that snapshot. `sa-total-memory-bytes` reports `heap-size`. These are estimates and separate calls can straddle a collection. Exercise retention and release of a large rooted bytevector across real collections. `sa-gc-collect` calls `gc`, maximum generation is 0, max-memory may report the current total and reset may no-op. Implement the maintain/observe hook over `after-gc-hook`, guarding recursive collections, propagating policy errors and measuring monotonic nanoseconds. Qualify callback context, timing and reentrancy through the actual policy before advertising a ceiling. Until then the installer returns `#f`. A finite OS address-space limit is a separate resource limit. Provide monotonic exact milliseconds for elapsed time and UTC epoch milliseconds for timestamps. [w6](witnesses/w6-gc-pinning.scm)

**Platform and I/O.** Derive OS family, canonical arch (`arm64`, `x86-64`) and OS release from the running process's `uname`, and endian from `native-endianness`. Use a stable `guile-<version>-<host>` tag for naming only. Read the environment in-process as name/value pairs, preserving values containing `=`. Implement `sa-run-process` with spawn, separate close-on-exec pipes and waitpid integration. Return four values in order (child stdin, stdout, stderr, pid), honor binary/text transcoding and close all partial resources on failure.

`sa-file-mtime-ms` calls fixed-arity C `stat(2)` through FFI **on both platforms**. Return status plus signed 64-bit seconds and normalized nanoseconds in caller-owned output storage. Read `st_mtimespec` on Darwin and `st_mtim` on Linux through their system headers. On success compute `1000 * sec + quotient(nsec, 1000000)` in exact Scheme integers. On failure consume boundary errno and raise for the path. This preserves pre-epoch time and avoids hard-coded offsets. Require `1700000000456` and `-9750` ms on actual files plus a missing-file error.

Open a dedicated read/write fd for the whole-file writer lock. The non-variadic C shim initializes `struct flock` from headers and calls `fcntl(fd, F_SETLK, &lock)` with `F_WRLCK` or `F_UNLCK`, `SEEK_SET`, zero start and length. Treat only `EACCES`/`EAGAIN` as contention. POSIX record locks are per-process and closing another fd for that inode can release them. Serialize acquisition by canonical directory/lock identity (device/inode), check existing holdings **before opening or closing another fd** for an alias, retain the one owner fd, and serialize unlock/close/removal. Keep lockfiles stable across ownership changes. Verify same-process aliases, rival process refusal while the owner remains active, and a successful acquisition after release. ## Risk register

| Risk | Detection and disposition |
| --- | --- |
| Ordinary loads bypass the synchronized record slot or the compiler moves accesses across a fence. | 3a inspects generated accessors, CAS indices and optimized lowering, then runs the real forcing paths on arm64. Hold threaded qualification until every reader of the publication word participates. |
| A fluid or shared virtual-register vector leaks state across forks. | 3a tests inherited bindings, isolated child clears, fresh registers and outside/inside ID agreement. Exercise the multi-threaded path from the first worker and foreign callback. |
| Seed drift or module shadowing appears only in live eval. | 3b replays full boot from an empty cache, compiles after reset and uses derived unbound/var/static/head checks. Compare emitted forms for all three targets. |
| A C trampoline outlives its root or runs Scheme before attachment. | 5 FFI tests actual public addresses across GC, concurrent foreign entry and quiescent release. Keep the collect-safe constructor refused until the helper passes on that ABI. |
| A Darwin-only ABI assumption survives development. | 3c and 5 run Linux witnesses and native fixtures. Derive struct fields/constants from headers, use boundary errno, assert negative mtime, contention and signed widths. Record loader/compiler identity with failures. |
| A hook firing is mistaken for enforceable heap policy. | 3a observes allocations, retain/release, nested collections and the real host maintenance callbacks. Gate the advertised policy on those results. |
| A crash or alias open drops the writer lock or publishes an incomplete HEAD. | 5 stores interleaves alias/rival opens with a live owner, injects failure before rename, restarts and verifies bytes, lock release and directory sync. |
| Crypto library availability or digest drift changes stored addresses. | 5 stores compares SHA-256, BLAKE3 and Ed25519 vectors, including rejected signatures, across both platforms before enabling the relevant capability. |
| Source startup or boxed mutable fields cost too much at application scale. | 4 records cold boot, time to first Yin prompt and warm eval on the same input as Chez. Keep correctness gates independent of timings. Use w12 as the Guile baseline and require source-equivalence evidence for any later bytecode-cache optimization. |
